# Accounts and first-use experience

Approved by the founder in chat on 2026-10-10. Build reader registration, verification/recovery, invitation-only team entry, account administration and light onboarding. Defer social login, long guided tours and advanced personalization.

Keep NextAuth credentials and Profile identities, so existing libraries, progress and assignments survive. Add emailVerifiedAt, disabledAt, authVersion, onboardingCompletedAt and preferredGenresJson. Migration trusts existing profiles; newly registered readers must verify before login. Seed/test factories must explicitly produce verified profiles. Registration never accepts a privileged role.

Use hashed, random, expiring, single-use verification/reset/invitation tokens. GET displays a confirmation form; only POST/server actions consume a token. Verification lasts 24 hours, reset 1 hour, team invitation 7 days. Tokens are bound to purpose/email/profile and rotation revokes earlier tokens. Atomic serializable consumption prevents duplicate acceptance. Existing-email invitation must not silently promote an account: signed-in matching verified account must explicitly accept; a new invitee sets a password. Invitation acceptance applies the stored role and revokes old sessions, with an audit record. Disabled accounts cannot regain access through reset or invitation.

Final review refinements: the mailbox owner chooses the effective password at verification, so an earlier signup by another person cannot choose it. Previously verified accounts cannot be overwritten by a verification token. Invitations record the issuing admin and authentication version; acceptance checks both inside its transaction. Limits are separated by operation and recipient, and trusted proxy client address when explicitly configured. Successful logins do not exhaust a victim's per-email failure counter; the direct-server shared safety ceiling is high, and public launch requires appropriate proxy/edge controls. Existing invite acceptance clearly requests a new sign-in.

Use database-backed request throttles across processes (email-specific and aggregate limits), including credential attempts. Responses for public recovery/resend and duplicate registration do not disclose existence. Validate normalized email, name 2–40 and passwords 12–128 characters. Changing or resetting password and account disabling increments authVersion; fresh session/DB checks reject revoked tokens. Keep last active verified administrator protected under concurrent changes. Record account role/status/invitation operations without secrets. Role changes retain current immediate DB authorization and assignment cleanup.

Server-only mail transport: local capture explicitly enabled only for saved loopback preview/isolated QA; SMTP requires configured host, port, credentials and sender, TLS enabled. Do not send external mail during implementation. Local captured mail is private filesystem data, not public assets/API; an admin-only local preview mailbox may display links. Never return raw tokens from public actions or logs. Trusted link origin comes from application configuration, never request Host. All destinations use a shared internal-path validator; reject scheme-relative, schemes, backslashes/control chars and auth-loop destinations.

Visitor discovery and public reading remain open. Save/follow links retain the current URL through login/registration/verification/onboarding. First login offers optional genre selection and an explicit skip, then returns to the destination. Profile supports name/bio, safe built-in avatar selection and password change. No arbitrary image uploads in this phase. Empty library/updates/profile states provide useful discovery links. Team invitations and account disabling are available to admin in /admin/users.

No external provider activation, production migration, deployment, content upload or SEO work. Gmail address was provided; prepare standard SMTP configuration and document that actual Gmail sending needs operator-owned credentials. Run isolated PostgreSQL security checks, one production build and focused desktop/mobile acceptance batch; one final read-only Claude review.
