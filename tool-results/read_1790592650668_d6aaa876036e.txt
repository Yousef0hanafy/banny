    87→   647→### ⚠️ Cover Content Overflow Prevention (Mandatory)
    88→   648→
    89→   649→1. Cover section page margin is 0; total content height ≤ 15638 twips (1200 twips safety margin for cross-engine compatibility — MS Office renders large fonts taller than calculated).
    90→   650→2. Color block Table `height` must use `rule: "exact"` (never `"atLeast"`).
    91→   651→3. Each recipe code includes height budget annotations — verify during generation.
    92→   652→4. **`verticalAlign` must always be `"top"`**. Never use `"center"` or `"bottom"` in exact-height rows — content will be clipped or overflow. Use `spacing.before` on the first paragraph for vertical positioning.
    93→   653→5. **Title font size MUST be dynamically calculated via `calcTitleLayout()`** (see below). Never hardcode font sizes above 40pt for cover titles. Every recipe MUST call `calcTitleLayout()` before building title paragraphs.
    94→   654→6. **Never use `margins.top`/`margins.bottom` for vertical positioning inside exact-height cells**: Cell margins reduce available height unpredictably across MS Office and WPS. Use `spacing.before` on the first paragraph instead. Only `margins.left`/`margins.right` are safe.
    95→   655→7. **Dynamic spacing is mandatory**: Use `calcCoverSpacing()` to compute `spacing.before` values dynamically based on content element count and title line count. Never use fixed large spacing values (e.g., `before: 4500`) that assume a specific title length.
    96→   656→8. **Cover must be a single-page section**: The cover section must produce exactly ONE page. If content overflows to a second page, it means the height budget is violated. Common overflow causes and fixes:
    97→   657→   - Title font too large → use `calcTitleLayout()` to auto-reduce
    98→   658→   - Too many meta lines → reduce font size or remove less important lines
    99→   659→   - Fixed `spacing.before` values too large → use `calcCoverSpacing()` for dynamic values
   100→   660→   - Subtitle + English label + meta lines combined exceed budget → calculate total and reduce spacing
   101→   661→9. **Cover wrapper table MUST use explicit `allNoBorders`**: The outer 16838 wrapper table and ALL nested tables inside the cover MUST set borders to NONE explicitly. Never rely on docx-js default borders (`single/auto/sz=4`). Default borders add ~8 twips per edge, which causes MS Office to calculate a total height slightly exceeding 16838 → content overflows to a blank page 2. WPS is more lenient but MS Office is strict. **This is the #1 cause of "blank page 2 in MS Office but not in WPS".**
   102→   662→
   103→   663→```js
   104→   664→// ✅ MANDATORY: Define and use allNoBorders for every cover table
   105→   665→const NB = { style: BorderStyle.NONE, size: 0, color: "FFFFFF" };
   106→   666→const noBorders = { top: NB, bottom: NB, left: NB, right: NB };
   107→   667→const allNoBorders = { top: NB, bottom: NB, left: NB, right: NB,
   108→   668→                       insideHorizontal: NB, insideVertical: NB };
   109→   669→
   110→   670→new Table({
   111→   671→  borders: allNoBorders,  // ← MANDATORY on every cover table
   112→   672→  // ...
   113→   673→});
   114→   674→```
   115→   675→
   116→   676→10. **Decorative lines MUST use paragraph borders, NEVER text characters**: Horizontal decorative lines (accent strips, dividers, frame edges) must be implemented with `paragraph border.top` or `border.bottom` — never with text characters like `───`, `━━━`, `═══`, or `——————`. Character-drawn lines render at inconsistent widths across MS Office and WPS (font metrics differ), causing lines to appear truncated or misaligned. Paragraph borders render pixel-perfect in both engines and their width is controlled precisely via `indent.left` / `indent.right`.
   117→   677→
   118→   678→```js
   119→   679→// ✅ Correct — paragraph border (R2 style thick accent rule)
   120→   680→new Paragraph({
   121→   681→  indent: { left: 1000, right: 1000 },
   122→   682→  border: { top: { style: BorderStyle.SINGLE, size: 18, color: P.accent, space: 20 } },
   123→   683→  children: [],
   124→   684→})
   125→   685→
   126→   686→// ❌ FORBIDDEN — text character line (renders inconsistently)
   127→   687→new Paragraph({
   128→   688→  children: [new TextRun({ text: "───────────────", color: P.accent })]
   129→   689→})
   130→   690→```
   131→   691→9. **Post-generation overflow check (mandatory)**: After building cover children, estimate total height:
   132→   692→   ```js
   133→   693→   function estimateCoverHeight(elements) {
   134→   694→     let total = 0;
   135→   695→     for (const el of elements) {
   136→   696→       if (el instanceof Table) {
   137→   697→         // Sum row heights (exact rows) or estimate 400 twips per row
   138→   698→         const rows = el.root?.[0]?.rows || [];
   139→   699→         for (const row of rows) {
   140→   700→           total += row.height?.value || 400;
   141→   701→         }
   142→   702→       } else if (el instanceof Paragraph) {
   143→   703→         const fontSize = el.root?.[0]?.size || 24; // half-pts
   144→   704→         // ★ Use pt * 11.5 (= half-pt * 10 * 1.15) for accurate single-spacing estimate
   145→   705→         const lineHeight = Math.max(fontSize * 11.5, 276); // min 276 (default 12pt)
   146→   706→         const spacingBefore = el.spacing?.before || 0;
   147→   707→         const spacingAfter = el.spacing?.after || 0;
   148→   708→         total += lineHeight + spacingBefore + spacingAfter;
   149→   709→       }
   150→   710→     }
   151→   711→     return total;
   152→   712→   }
   153→   713→   // ★ Target: estimateCoverHeight(coverChildren) < 15638 (16838 - 1200 safety)
   154→   714→   ```

   158→   718→### ⚠️ Cover Title Layout — calcTitleLayout() (Mandatory for ALL Recipes)
   159→   719→
   160→   720→**Every cover recipe MUST use `calcTitleLayout()` to determine title font size and line breaks.** Hardcoding font sizes or passing the full title as a single TextRun is FORBIDDEN.
   161→   721→
   162→   722→**Every paragraph with font size > body text MUST set explicit line spacing** to prevent top clipping:
   163→   723→```js
   164→   724→// ★ MANDATORY: prevent inherited small line spacing from clipping large fonts
   165→   725→spacing: { line: Math.ceil(titlePt * 23), lineRule: "atLeast", after: 100 }
   166→   726→// Example: 36pt → line: 828; 44pt → line: 1012
   167→   727→```
   168→   728→Without this, the paragraph inherits body text line spacing (e.g., 560tw), which is shorter than the font height → top of characters gets clipped.
   169→   729→
   170→   730→```js
   171→   731→/**
   172→   732→ * Calculate safe font size and smart line breaks for cover titles.
   173→   733→ * MUST be called by every recipe before building title paragraphs.
   174→   734→ *
   175→   735→ * @param {string}  title          Full title string
   176→   736→ * @param {number}  maxWidthTwips  Available width for title text (twips, after subtracting margins/padding)
   177→   737→ * @param {number}  preferredPt    Desired max font size in pt (default 40)
   178→   738→ * @param {number}  minPt          Minimum allowed font size in pt (default 24)
   179→   739→ * @returns {{ titlePt: number, titleLines: string[] }}
   180→   740→ */
   181→   741→function calcTitleLayout(title, maxWidthTwips, preferredPt = 40, minPt = 24) {
   182→   742→  // Each CJK character width ≈ pt × 20 twips
   183→   743→  const charWidth = (pt) => pt * 20;
   184→   744→  const charsPerLine = (pt) => Math.floor(maxWidthTwips / charWidth(pt));
   185→   745→
   186→   746→  // Try from preferredPt downward until title fits in ≤ 3 lines
   187→   747→  let titlePt = preferredPt;
   188→   748→  let lines;
   189→   749→  while (titlePt >= minPt) {
   190→   750→    const cpl = charsPerLine(titlePt);
   191→   751→    if (cpl < 2) { titlePt -= 2; continue; }
   192→   752→    lines = splitTitleLines(title, cpl);
   193→   753→    if (lines.length <= 3) break;
   194→   754→    titlePt -= 2;
   195→   755→  }
   196→   756→
   197→   757→  // If still > 3 lines at minPt, force 3 lines
   198→   758→  if (!lines || lines.length > 3) {
   199→   759→    const cpl = charsPerLine(minPt);
   200→   760→    lines = splitTitleLines(title, cpl);
   201→   761→    titlePt = minPt;
   202→   762→  }
   203→   763→
   204→   764→  return { titlePt, titleLines: lines };
   205→   765→}
   206→   766→
   207→   767→/**
   208→   768→ * Smart Chinese title line-breaking — breaks at semantic boundaries, never mid-word.
   209→   769→ *
   210→   770→ * Rules:
   211→   771→ * 1. Prefer breaking after particles, punctuation, connectors, underscores, spaces
   212→   772→ * 2. Never split a compound word (e.g., "管理规范" must not become "管理规" + "范")
   213→   773→ * 3. No single-character orphan on the last line — merge into previous line
   214→   774→ * 4. If no good break point found within 60-130% of charsPerLine, break at charsPerLine
   215→   775→ *
   216→   776→ * @param {string} title        Full title string
   217→   777→ * @param {number} charsPerLine Max characters per line at current font size
   218→   778→ * @returns {string[]}          Array of line strings
   219→   779→ */
   220→   780→function splitTitleLines(title, charsPerLine) {
   221→   781→  if (title.length <= charsPerLine) return [title];
   222→   782→
   223→   783→  // Characters that are safe break points (break AFTER these)
   224→   784→  const breakAfter = new Set([
   225→   785→    ...'，。、；：！？',              // CJK punctuation
   226→   786→    ...'的与和及之在于为',            // CJK particles/prepositions
   227→   787→    ...'-_—–·/',                     // connectors
   228→   788→    ...' \t',                         // whitespace
   229→   789→  ]);
   230→   790→
   231→   791→  const lines = [];
   232→   792→  let remaining = title;
   233→   793→
   234→   794→  while (remaining.length > charsPerLine) {
   235→   795→    let breakAt = -1;
   236→   796→
   237→   797→    // Search backward from charsPerLine to 60% for a break point
   238→   798→    for (let i = charsPerLine; i >= Math.floor(charsPerLine * 0.6); i--) {
   239→   799→      if (i < remaining.length && breakAfter.has(remaining[i - 1])) {
   240→   800→        breakAt = i;
   241→   801→        break;
   242→   802→      }
   243→   803→    }
   244→   804→
   245→   805→    // If not found, search forward up to 130%
   246→   806→    if (breakAt === -1) {
   247→   807→      const limit = Math.min(remaining.length, Math.ceil(charsPerLine * 1.3));
   248→   808→      for (let i = charsPerLine + 1; i < limit; i++) {
   249→   809→        if (breakAfter.has(remaining[i - 1])) {
   250→   810→          breakAt = i;
   251→   811→          break;
   252→   812→        }
   253→   813→      }
   254→   814→    }
   255→   815→
   256→   816→    // Last resort: break at charsPerLine, but avoid splitting compound CJK words
   257→   817→    if (breakAt === -1) {
   258→   818→      breakAt = charsPerLine;
   259→   819→      // If both chars at the break boundary are CJK (likely a compound word),
   260→   820→      // step back 1 char to keep the word together
   261→   821→      const prevChar = remaining[breakAt - 1];
   262→   822→      const nextChar = remaining[breakAt];
   263→   823→      if (prevChar && nextChar &&
   264→   824→          !breakAfter.has(prevChar) && !breakAfter.has(nextChar) &&
   265→   825→          /[\u4e00-\u9fff]/.test(prevChar) && /[\u4e00-\u9fff]/.test(nextChar)) {
   266→   826→        breakAt = breakAt - 1;
   267→   827→      }
   268→   828→    }
   269→   829→
   270→   830→    lines.push(remaining.slice(0, breakAt).trim());
   271→   831→    remaining = remaining.slice(breakAt).trim();
   272→   832→  }
   273→   833→  if (remaining) lines.push(remaining);
   274→   834→
   275→   835→  // Prevent single-character orphan on last line — merge into previous
   276→   836→  if (lines.length > 1 && lines[lines.length - 1].length <= 2) {
   277→   837→    const last = lines.pop();
   278→   838→    lines[lines.length - 1] += last;
   279→   839→  }
   280→   840→
   281→   841→  return lines;
   282→   842→}
   283→   843→
   284→   844→/**
   285→   845→ * Calculate dynamic spacing values for cover elements to fit within page height.
   286→   846→ *
   287→   847→ * @param {object} params
   288→   848→ * @param {number} params.titleLineCount   Number of title lines
   289→   849→ * @param {number} params.titlePt          Title font size in pt
   290→   850→ * @param {boolean} params.hasSubtitle     Whether subtitle exists
   291→   851→ * @param {boolean} params.hasEnglishLabel Whether English label exists
   292→   852→ * @param {number} params.metaLineCount    Number of meta info lines
   293→   853→ * @param {number} params.fixedHeight      Sum of fixed-height elements (color strips, accent bars, footer) in twips
   294→   854→ * @param {number} params.pageHeight       Total page height in twips (default 16838)
   295→   855→ * @returns {{ topSpacing, midSpacing, bottomSpacing }}  Spacing values in twips
   296→   856→ */
   297→   857→function calcCoverSpacing(params) {
   298→   858→  const {
   299→   859→    titleLineCount = 1, titlePt = 36, hasSubtitle = false,
   300→   860→    hasEnglishLabel = false, metaLineCount = 0,
   301→   861→    fixedHeight = 800, pageHeight = 16838,
   302→   862→    marginTop = 0, marginBottom = 0,   // ★ NEW: pass actual section margins
   303→   863→  } = params;
   304→   864→
   305→   865→  // ★ Safety margin: 1200 twips (cross-engine: MS Office renders large fonts
   306→   866→  // taller than calculated; extra 400tw buffer prevents footer clipping)
   307→   867→  const SAFETY = 1200;
   308→   868→  // ★ Subtract page margins from available height (cover section may have margins)
   309→   869→  const usableHeight = pageHeight - marginTop - marginBottom - SAFETY;
   310→   870→
   311→   871→  // ★ Accurate height estimation per element:
   312→   872→  const titleHeight = titleLineCount * (titlePt * 23 + 200);
   313→   873→  const subtitleHeight = hasSubtitle ? (12 * 23 + 600) : 0;
   314→   874→  const englishLabelHeight = hasEnglishLabel ? (9 * 23 + 600) : 0;
   315→   875→  const metaHeight = metaLineCount * (10 * 23 + 100);
   316→   876→
   317→   877→  // ★ Account for implicit paragraph heights:
   318→   878→  const implicitParaHeight = 3 * 300;
   319→   879→
   320→   880→  const contentHeight = titleHeight + subtitleHeight + englishLabelHeight +
   321→   881→                        metaHeight + fixedHeight + implicitParaHeight;
   322→   882→
   323→   883→  const remainingSpace = usableHeight - contentHeight;
   324→   884→  const safeRemaining = Math.max(remainingSpace, 400);
   325→   885→
   326→   886→  // ★ Footer protection: bottomSpacing must be ≥ FOOTER_MIN to prevent
   327→   887→  // footer + accent line from being clipped at the cell bottom edge
   328→   888→  const FOOTER_MIN = 800;
   329→   889→  const rawTop = Math.floor(safeRemaining * 0.45);
   330→   890→  const rawBottom = Math.floor(safeRemaining * 0.45);
   331→   891→  const bottomSpacing = Math.max(rawBottom, FOOTER_MIN);
   332→   892→  const topSpacing = Math.max(rawTop - Math.max(0, FOOTER_MIN - rawBottom), 400);
   333→   893→  const midSpacing = Math.max(safeRemaining - topSpacing - bottomSpacing, 0);
   334→   894→
   335→   895→  return { topSpacing, midSpacing, bottomSpacing };
   336→   896→}
   337→   897→```
   338→   898→
   339→   899→**Usage in every recipe:**

   345→   905→

   348→   908→  titleLineCount: titleLines.length,
   349→   909→  titlePt,
   350→   910→  hasSubtitle: !!config.subtitle,
   351→   911→  hasEnglishLabel: !!config.englishLabel,
   352→   912→  metaLineCount: (config.metaLines || []).length,
   353→   913→  fixedHeight: 800, // sum of accent strips, footer table, etc.
   354→   914→  marginTop: 0,     // ★ pass the cover section's actual top margin (twips)
   355→   915→  marginBottom: 0,  // ★ pass the cover section's actual bottom margin (twips)

   357→   917→
   358→   918→// Step 3: Use in paragraphs
